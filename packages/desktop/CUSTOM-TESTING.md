# AIOStreams Custom — seek previews, revision 8

Windows x64 portable test build. Cached Debrid supports background fill. Usenet supports hover requests only in this first test. Close the old app and extract into a fresh folder. Keep the ZIP's files together. You may copy the old `data` folder while both apps are closed to retain settings; the collector also includes any older preview logs copied with it.

## Launch 1 — default, Debrid then Usenet

Double-click **Start-Default.cmd**. Turn previews on in **Settings → Playback → Controls**. No PowerShell settings are needed. If startup is black, close and relaunch; note that it happened. Each launch writes a new log, and previous logs remain.

1. **Debrid: same LOTR remux.** Once playback has shown a frame, hover six distant, previously unvisited positions for five seconds each. Suggested positions: 20:00, 40:00, 60:00, 80:00, 100:00 and 120:00. Note the delay on the first hover, whether each image arrives within five seconds, colours and any playback buffering. Repeat the six positions to check cached speed.
2. **LOTR background fill.** Move away from the bar and play untouched for ten minutes. Then slowly sweep the whole timeline once, noting any loading gaps. Check near playback, ±5 minutes and ±15 minutes. Background now targets at most 240 positions, roughly 57 seconds apart for this particular file. Repeating an image across a wider part of the timeline is expected; the timestamp always follows the pointer. Ten minutes is a measurement window, not a promised fill deadline.
3. **SDR and the same 4K HDR episode.** For each, hover three new distant positions for five seconds each, then play hands-off for three minutes and sweep once. Note loading gaps, colours and buffering. Episode spacing scales with runtime too (approximately 6 seconds for 24 minutes and 8.4 seconds for 34 minutes).
4. **Chapters and box stability.** On a file with chapters, check the chapter name or a numbered fallback alongside the timestamp. Long names should end in an ellipsis. On a file without chapters, only the timestamp should appear. Sweep and cross chapter boundaries: the image box must stay at the same vertical position and hide immediately when leaving the bar. Loading and unavailable states keep the same frame size.
5. **Recovery.** Before disconnecting, reset the preview cache by turning previews off and on. Wait for the playing video to have a frame, then hover a distant new position and disconnect your PC's network for about twenty seconds while keeping the pointer there. Reconnect and hold the hover for up to forty-five seconds. Record whether an image returns without restarting the app. Main playback may buffer because you deliberately disconnected it; note that separately. This test must use a cold position, since cached thumbnails do not need the network. If a distant main-player seek buffers naturally, also try hovering another new position during that interval.
6. **Usenet: switch servers in this same launch.** Log out of the Debrid server and log into your Usenet Jellyfin server. Logs continue with new video session IDs and `source_kind=usenet`; there is no need to collect between servers. Play an SDR release hands-off for two minutes, then hover near playback and three widely separated new positions for five seconds each. Repeat the same positions. The first preview decoder opens on the first hover; there is no Usenet background scan. You only need to hover, not click or seek the playing video. Note first-hover delay, later cold delays, cached speed and main playback buffering.
7. **Real Usenet DV P5 release.** Repeat that hover test. Report natural colours, green/purple colours, loading that never completes, or “Preview unavailable.” Do the same for P8 if readily available. The logs now distinguish decoder-confirmed DV from a server hint; natural colours by themselves do not establish the profile. No background fill is expected on either Usenet release.

Close the app after these tests.

## Launch 2 — combined fast-seek experiment, Debrid only

Double-click **Start-Fast-Seek.cmd**. It applies the combined experiment without any PowerShell commands. Switch back to the Debrid server if necessary.

- Repeat the same six LOTR positions before leaving it to fill. Hold each for five seconds, then repeat them. Use the same release as Launch 1.
- Repeat the three cold positions on the same 4K HDR episode. Note colours, whether images appear faster, and playback buffering.

Close the app. Do not run default and fast-seek simultaneously. The experiment changes only the private preview decoder. It combines persistent HTTP requests, skipping the decoder loop filter and disabling MKV end-duration probing. It remains an experiment: no provider-speed improvement is claimed until the comparison logs support it.

## Collect once, after both launches

In this extracted folder, double-click **Collect-Preview-Logs.cmd** after closing the app. Wait for **Created Preview-Logs.zip with … logs**. Attach **Preview-Logs.zip**, optionally renamed **v8-preview-logs.zip**.

**Do not collect between files, servers or launches.** The collector includes all timestamped preview logs present and replaces the ZIP each time. Black-screen relaunches keep earlier logs; force-closing can omit a session's final summary. Ordinary application logs are excluded because they can contain authenticated stream URLs.

## Changes to relay

- Replaced the fixed 5/8-second schedule with `max(5 seconds, runtime / 240)`, rounded upward to a millisecond. Examples: 10 minutes → 5 seconds; 24 minutes → 6 seconds; 1 hour → 15 seconds; 2 hours → 30 seconds; 4 hours → 60 seconds. There are at most 240 positions per supported video (up to 24 hours). Hover, background fill, cache coverage and UI lookup all use that same grid. End-of-timeline requests use the final valid slot. A shared one-microsecond tolerance prevents floating-point gaps at slot edges, and the native slot count is explicitly capped at 240. This reduces whole-file extraction work while making long-film previews less precise.
- Both image caches cap at 240 images and retain the 24 MiB encoded-data ceiling; neither reserves that memory up front. At V7's image sizes, a complete LOTR grid is about 1.7 MiB of encoded image text in each cache. This does not measure decoded-image or whole-player memory.
- Background duty follows observed buffer health: 25% at 10–30 seconds while the main reader is active; 50% with at least 30 seconds buffered or an idle main reader; 80% with both at least 30 seconds and an idle reader. It stays off below ten seconds, with unknown health, during pause/seek/buffering and while hovering. A main buffering event caps duty at 25% for two minutes after recovery. No parallel preview workers were added.
- Removed the extra per-capture delay that competed with duty-cycle scheduling. The final portion of a rest is waited exactly; hover/stop notifications wake the worker immediately. Health polling remains bounded to 100 milliseconds.
- Added a `fast-seek` combined experiment and dedicated launcher. Default colour conversion and seek options stay the baseline pending testing. Old individual options remain for developer diagnostics; the Windows fixture comparison uses the new combined experiment.
- Decoder initialization gets three attempts before being treated as unsupported for that session. Ordinary remote open/seek failures still retry with backoff and reopen only the private decoder. Demand has no cumulative work cutoff; cached images remain available during retry. An authenticated HTTP outage fixture checks failed-open recovery, and policy tests check repeated timeouts and initialization retries. The twenty-second manual drop still tests the real provider and its stalled-seek path.
- Opening/opened logs include `dv_profile_source`, `dv_hint`, `dv_decoder`, `decoded_gamma`, `decoded_matrix` and `dv_hint_mismatch`. A lone P5 server hint is rejected when the actual decoder parameters establish a non-DV colour matrix; the decoded transfer then selects HDR10/HLG/SDR conversion. A decoder-confirmed P5 profile or DV matrix retains the P5 conversion path. Missing decoder evidence does not establish a false label. A plain HDR10 fixture with a false P5 hint checks this guard separately from the real P5 fixture.
- Logs add the minimum observed main buffer for each thirty-second interval, current duty and throttle state. Queue-byte changes and their positive cumulative growth are logged as **packet-cache storage only**. mpv's `total-bytes` includes retained packets and overhead, so these are not actual network-byte measurements. Accurate transferred traffic still requires a network counter or transport instrumentation; queue growth is deliberately not called `bytes_read_delta`.
- The tooltip uses real chapter names, a chapter number when the file has an unnamed chapter, and only the hovered timestamp when no chapter exists. Names truncate on one line. Images, loading and unavailable keep one fixed frame and one fixed-height label row, so retry state cannot collapse the box.
- Added Usenet demand-only eligibility and native enforcement. It opens on first hover and reuses the same bounded single decoder/cache. No eager open, background fill or extra worker is allowed. One preview decoder is not a guarantee of one NNTP provider connection; the streaming backend controls those. Client fixtures verify the scheduling policy, but real Usenet seeks and P5 colours still require this test run.

Provider latency, data volume per seek and available playback buffer can still dominate cold-hover time. A coarser grid makes filling faster; it does not automatically make an individual remote seek faster.
