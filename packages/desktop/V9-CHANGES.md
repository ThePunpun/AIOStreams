# Seek previews V9 — changes from V8 and implementation decisions

Baseline: `7d735af318e89bb8e66de3af7fedbcd7d4598d97`. The separate `v8-to-v9.patch` contains the exact source diff, including these notes and the test guide. The supplied feedback's V8 measurements are reported baseline results; this build does not reinterpret unseen original logs.

## Changes implemented

1. **Learned, frozen grid.** Budget = `clamp(round(480 × 0.5 / cold_capture_cost_s), 240, 600)`; interval = `max(5, ceil(runtime_s × 1000 / budget) / 1000)`. The interval freezes after the main player's first frame and valid duration; successful cold captures train subsequent sessions only. A bounded rolling median uses the last 31 successful samples, requiring five before replacing defaults. Opening frames, failed work, cached decoder seeks and costs outside 0.05–15 seconds are excluded. Classes are source kind × SDR/HDR/DV × width up to/above 1920 pixels. Only these class names and costs persist in `data/preview-seek-costs.json`; URLs, titles and credentials do not. Invalid/missing history falls back to defaults. Native and UI caches both cap at 600 images and retain the 24 MiB encoded-data ceiling.

   Defaults: Debrid/HTTP SDR up to 1080p = 0.35 s, HDR/DV or wider = 0.9 s; Usenet SDR up to 1080p = 0.3 s, HDR/DV or wider = 0.75 s. An unknown colour or width uses a conservative class. `grid_slots` logs actual timeline points; `grid_budget_slots` logs the calculated ceiling. `grid_cost_s`, `grid_cost_source`, `grid_class` and `grid_learning` make the choice reviewable.

2. **Stable-buffer controller.** Debrid starts at 50% duty with at least ten seconds buffered, then promotes through 65% to 80% after consecutive 30-second stable observation windows. Promotions require a minimum buffer of ten seconds and no greater than a 20% drop from the previous minimum. A greater than 25% drop steps down. Hovering, seeking, buffering, input underrun, unknown buffer health and fewer than ten seconds buffered block background work. Paused playback may fill under the same health rules. No additional preview worker or decoder runs in parallel.

3. **Seek versus underrun.** Accepted main-player seek commands are marked directly; observed seek flags and playhead jumps provide fallback evidence. Expected clock advance accounts for playback speed and pause. A stalled clock is not mistaken for a seek. A seek-induced buffering episode does not gain an underrun cooldown even if it lasts more than five seconds. Genuine underruns use a 60-second 25% backoff after recovery. An underrun observed after duty above 50% reduces that session's ceiling one level. Logs include cause, previous effective duty, controller level/reason, pause state and trailing buffer minima.

4. **Usenet background, stage 1.** Full mode is enabled, but background requires a complete observed 60-second window with at least 30 seconds buffered, an idle main reader and no main buffering in the last five minutes. Observation gaps longer than ten seconds invalidate the window. Duty is capped at 25%; at most 30 background seek attempts are issued in a rolling minute. In-flight background work aborts if the main buffer falls below twenty seconds, buffering/seeking starts or the main reader resumes. Playback-health cancellations close the private decoder so its read cannot continue unnoticed. Demand keeps priority. `Start-Usenet-Demand-Only.cmd` sets `AIOSTREAMS_PREVIEW_USENET_BACKGROUND=off`. One decoder does not determine the streaming backend's NNTP connection count.

5. **Finite HTTP, demand only.** HTTP sources can open on an accepted hover; no eager open or background scan. The private decoder must report seekable and explicitly not partially seekable. Unsupported HTTP becomes unavailable in the existing fixed frame. Live/infinite, P2P, unknown kinds, uncached Debrid and unsupported direct-play sources remain off. Source-kind changes reset the frontend session even when the URL and mode match. The settings help now describes supported desktop streams rather than only cached Debrid. Missing/unsupported durations become unavailable after a bounded wait; a later valid duration can recover the session.

6. **Open timeout and P5 labels.** The initial frame wait starts at five seconds. Usenet may extend once to fifteen seconds only while mpv reports input underrun and recent packet growth or a positive input-rate estimate. Actual filter errors retain filter-failure labels; generic initialization, decode and open timeouts do not claim a P5 filter failure. Open failures log `stage=open`. These timeouts do not consume the three decoder-initialization attempts. Existing recoverable remote failures and the absence of a cumulative demand cutoff are preserved.

7. **Hover metric.** The first cold-hover timer starts on an accepted request after the frontend's 75 ms settle, not on timeline entry. Leaving before display or clearing unsettled intent resets it. Logs identify `hover_timer=settled-demand`; `hover_to_image_ms` remains the separate frontend measurement including its settle/display time.

8. **Wide-source ordering and P8.** Wide files use four-slot forward batches, two ahead batches then one behind; backward-frontier batches are read in forward order. Cached coverage is rechecked and large playhead movement replans work. Compatible decoder-confirmed P8/P9 bases now use their decoded PQ/HLG/SDR transfer when no server range hint exists. P5 libplacebo and P7 HDR10-base handling remain. Real P8 colour accuracy requires the tester's file.

9. **Controlled fast-seek comparison.** The experiment remains unpromoted. `Start-Comparison-Default.cmd` and `Start-Fast-Seek.cmd` disable cost training, so both runs read the same unchanged cost history and choose matching grids. Fast-seek combines persistent HTTP, skipped decoder loop filtering and disabled MKV duration probing. `Start-Default.cmd` enables normal learning again.

10. **Regression checks.** Added policies for the four requested grid examples, median persistence/corruption, controller promotion/drop/ceiling, long seek stalls, stalled clocks, paused fill, Usenet health/rate gating, HTTP partial-seek rejection and adaptive timeout bounds. Real authenticated HTTP fixtures exercise outage recovery, HTTP demand-only behaviour, paused background fill and a server refusing Range requests. Existing HDR/HLG, aspect, cancellation, cache-boundary, main-player independence and P5 fallback checks remain.

## Deviations from the feedback, and why

- **No guaranteed 45-second LOTR interval on first launch.** There is no measured V9 history yet. With the specified 0.9 s default, its first budget is 267 and spacing about 51.28 s. At a learned 0.78 s it becomes 308/about 44.45 s on a later session. A class median mixes files and providers within that class; it is not a per-file promise. Neither five-minute fill nor a specific capture rate is guaranteed before real testing.
- **No idle-reader shortcut to Debrid's top duty.** An idle reader alone does not establish spare provider throughput. Promotions require the same 30-second stable windows whether the reader is idle or active. Usenet retains the stricter idle requirement.
- **No guessed network/decode split.** mpv exposes approximate reader timestamps and estimated rates, not a reliable first packet for a particular seek. `network_wait_ms` and `decode_ms` explicitly remain unavailable. Queue-byte changes continue to mean packet storage, not transferred traffic. The Usenet timeout extension uses an explicitly labelled progress estimate, not a measured byte counter.
- **Comparison runs do not train the baseline.** Otherwise a faster experimental decoder could change the next default grid, and learning between two comparison files could give them different sampling grids. Two dedicated comparison launchers keep that confound out of the paired trial.
- **Four-frame batches, rather than an unchecked moving ring.** Each batch is bounded and revalidated against actual coverage. This reduces direction changes without creating skipped slots as playback moves. No speed gain is claimed yet.
- **Live/P2P and parallel previews remain outside this test.** Their off policies are checked in automated tests; the manual guide does not ask you to add or test them.

Chapter names, ellipsis, fixed tooltip dimensions, instant hide and user-facing preview settings are retained from V8. This remains a desktop prototype; web trickplay and actual transport-byte instrumentation are separate work.
